# Browser compatibility

The existing validation workflow calls the shared TypeScript/browser pipeline.
Pull requests run five required targets: current Chromium, Firefox and WebKit on
Linux, Chromium on Windows, and WebKit on macOS. Scheduled and manual validation
run all 35 declared targets: three pinned Playwright/browser generations on each
OS, installed Chrome/Edge Stable on each OS, and Chrome/Edge Beta on Linux.
Every target must pass; GitHub-hosted runners remain the default.

`scripts/browser-acceptance.cjs` serves the committed `index.html` unchanged and
uses synthetic same-origin HTTP responses. It tests real rendered telemetry and
phase sums, the 15-second snapshot and 60-second health polling schedules, HTTP
and malformed-response errors, recovery, an old response arriving after a newer
success, untrusted status text, and mobile/keyboard navigation. Browser clocks
advance the original timers. No plant, gateway, account or production credentials
are used; unexpected outbound requests fail the suite.

The long-status mobile case protects against table content stretching cards
beyond the viewport. On WebKit, link navigation uses its default Option+Tab
shortcut; other engines use Tab. Each successful target records the actual
browser version, named scenarios and the page SHA-256; traces and failure
screenshots are retained by the shared workflow.

This is validation-only source acceptance. It does not publish an application
release or prove a deployed proxy's credentials, real plant availability or
physical-device behavior. Playwright WebKit is not Apple's Safari product, and
the mobile viewport is not a real phone. Keep deployment checks separate.

The isolated locks under `tools/browser-compatibility/` and inventory in
`.github/browser-compatibility.json` are generated by
`venus-os-ci-toolkit/scripts/prepare_browser_compatibility.py`. Refresh them
together and review the actual browser versions. Local code checks remain
`bash scripts/ci.sh`; the browser adapter expects the runtime/evidence environment
provided by the shared pipeline.
